# ダイクストラ法

## 考え方

**ダイクストラ法（Dijkstra's algorithm）** は、重みが 0 以上のグラフで単一始点最短経路を求めるアルゴリズムです。

1. `d[始点] = 0`、それ以外は `d[v] = INF` とする。すべての頂点を「未確定」にする
2. 未確定の頂点のうち、`d[u]` が**最小**の頂点 `u` を選び、「確定」にする
3. `u` から出るすべての辺 `u → v` について**緩和**する（`d[u] + w < d[v]` なら更新）
4. すべての頂点が確定するまで 2〜3 を繰り返す

:::important[なぜ最小の頂点は確定してよいのか]
重みが 0 以上なので、まだ未確定の他の頂点を経由しても、`u` への距離が `d[u]` より短くなることはありません
（経由する頂点の時点ですでに `d[u]` 以上の距離がかかっているからです）。
だから「今一番近い頂点」はその時点で最短距離が確定します。**負の辺があるとこの理屈が崩れます**。
:::

## 動きを追ってみる

AOJ ALDS1_12_B のサンプル入力のグラフ（有向）で、始点 `0` から実行してみます。

```
辺の一覧（u → v : 重み）
0 → 1 : 2    0 → 2 : 3    0 → 3 : 1
1 → 0 : 2    1 → 3 : 4
2 → 0 : 3    2 → 3 : 1    2 → 4 : 1
3 → 0 : 1    3 → 1 : 4    3 → 2 : 1    3 → 4 : 3
4 → 2 : 1    4 → 3 : 3
```

| ステップ | 確定する頂点 | d[0] | d[1] | d[2] | d[3] | d[4] |
|:---|:---|:---|:---|:---|:---|:---|
| 初期状態 | - | **0** | ∞ | ∞ | ∞ | ∞ |
| 1 | 0（距離 0） | **0** | 2 | 3 | 1 | ∞ |
| 2 | 3（距離 1） | **0** | 2 | 2 | **1** | 4 |
| 3 | 1（距離 2） | **0** | **2** | 2 | **1** | 4 |
| 4 | 2（距離 2） | **0** | **2** | **2** | **1** | 3 |
| 5 | 4（距離 3） | **0** | **2** | **2** | **1** | **3** |

太字は確定済みの値です。

- ステップ2: 頂点 `3` を経由すると `d[2]` が `3 → 2`、`d[4]` が `∞ → 4` に更新される
- ステップ4: 頂点 `2` を経由すると `d[4]` が `4 → 3` に更新される

最終的な答えは `d = [0, 2, 2, 1, 3]` で、サンプル出力と一致します。

## O(V^2) の実装（AOJ ALDS1_12_B）

ALDS1_12_B は `n <= 100` なので、隣接行列を使い、「最小の頂点を探す」を毎回 `for` 文で全頂点から探しても十分間に合います。

### 入力形式

```
n
u k v1 c1 v2 c2 ... vk ck    （n 行。頂点 u から vi へ重み ci の辺）
```

頂点番号は `0..n-1`、始点は `0` です。出力は各頂点の `番号 最短距離` です。

### 解答例（C）

```c
#include <stdio.h>

#define INF 2000000000

int n;
int M[100][100];
int d[100];
int done[100];   /* 1: 確定済み */

int main(void) {
    scanf("%d", &n);
    for (int i = 0; i < n; i++)
        for (int j = 0; j < n; j++) M[i][j] = -1;   /* -1: 辺なし */

    for (int i = 0; i < n; i++) {
        int u, k;
        scanf("%d %d", &u, &k);
        for (int j = 0; j < k; j++) {
            int v, c;
            scanf("%d %d", &v, &c);
            M[u][v] = c;
        }
    }

    for (int i = 0; i < n; i++) d[i] = INF;
    d[0] = 0;

    for (int step = 0; step < n; step++) {
        /* 未確定の頂点のうち d が最小のものを探す */
        int u = -1;
        for (int i = 0; i < n; i++) {
            if (!done[i] && d[i] != INF && (u == -1 || d[i] < d[u])) u = i;
        }
        if (u == -1) break;   /* もう到達できる頂点がない */
        done[u] = 1;

        /* u から出る辺で緩和 */
        for (int v = 0; v < n; v++) {
            if (M[u][v] != -1 && d[u] + M[u][v] < d[v]) {
                d[v] = d[u] + M[u][v];
            }
        }
    }

    for (int i = 0; i < n; i++) printf("%d %d\n", i, d[i]);
    return 0;
}
```

:::warning[INF の足し算に注意]
`d[u] == INF` の頂点から緩和すると `INF + c` が `int` の範囲を超えてあふれ（オーバーフロー）、負の値になることがあります。
上のコードは `d[i] != INF` の頂点だけを選ぶので、`d[u] + M[u][v]` があふれることはありません。
:::

## 計算量

| 処理 | 回数 | 1回あたり | 合計 |
|:---|:---|:---|:---|
| 最小の頂点を探す | `V` 回 | `O(V)` | `O(V^2)` |
| 緩和（隣接行列） | `V` 回 | `O(V)` | `O(V^2)` |

全体で **`O(V^2)`** です。`V = 100` なら `10^4` 程度で一瞬ですが、
`V = 10000` だと `10^8` になり、隣接行列のメモリ（`10^8` 個の `int` = 400MB）も足りません。
