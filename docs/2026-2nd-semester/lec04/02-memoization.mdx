# メモ化

## 問題: 単純な再帰は遅い

前回学んだフィボナッチの再帰実装を思い出してください。

```c
int fib(int n) {
    if (n <= 1) return n;
    return fib(n - 1) + fib(n - 2);
}
```

`fib(5)` の呼び出し木は次のようになります。

```
              fib(5)
            /        \
        fib(4)        fib(3)
       /      \       /     \
   fib(3)   fib(2) fib(2) fib(1)
   /   \    /  \   /  \
 ...   ... ... ... ... ...
```

`fib(3)` や `fib(2)` が**何度も同じ計算**をされています。
そのため計算量はおよそ `O(2^N)` で、`n = 40` 程度で実用に耐えません。

## メモ化とは

**メモ化（memoization）** は、一度計算した答えを配列（メモ）に覚えておき、同じ引数が来たら再利用する手法です。
再帰の構造はそのまま（トップダウン）で、無駄な再計算だけを消します。

```c
#include <stdio.h>
#include <string.h>

int memo[100];

int fib(int n) {
    if (n <= 1) return n;
    if (memo[n] != -1) return memo[n];   // 計算済みなら返す
    return memo[n] = fib(n - 1) + fib(n - 2);
}

int main(void) {
    memset(memo, -1, sizeof(memo));  // 未計算を -1 で初期化
    printf("%d\n", fib(40));         // 一瞬で終わる
    return 0;
}
```

### 計算量

| 実装 | 計算量 | 理由 |
|:-----|:-------|:-----|
| 単純な再帰 | `O(2^N)` | 同じ部分問題を指数回計算 |
| メモ化 | `O(N)` | 各 `n` について1回だけ計算 |

:::tip[初期値の約束]
「まだ計算していない」ことを表す値を決めます。
フィボナッチなら答えは非負なので `-1` が便利です。
答えが負にもなりうる問題では、別のフラグ配列を使うこともあります。
:::

## 部分和へのメモ化（ALDS1_5_A の高速化イメージ）

前回の全探索 `solve(i, m)` も、同じ `(i, m)` を何度も訪れることがあります。
2次元のメモを使うと高速化できます。

```c
int memo[50][2001];  /* -1: 未計算, 0: no, 1: yes */

int solve(int i, int m) {
    if (m == 0) return 1;
    if (i >= n || m < 0) return 0;
    if (memo[i][m] != -1) return memo[i][m];

    int res = 0;
    if (solve(i + 1, m)) res = 1;                      /* 使わない */
    else if (solve(i + 1, m - a[i])) res = 1;           /* 使う */
    return memo[i][m] = res;
}
```

状態数が `O(N × M)`、各状態の遷移が定数時間なので、全体で `O(N M)` になります。
