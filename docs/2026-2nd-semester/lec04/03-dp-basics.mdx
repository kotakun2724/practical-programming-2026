# 動的計画法の基礎

## 動的計画法（DP）とは

**動的計画法（Dynamic Programming, DP）** は、大きな問題を小さな部分問題に分け、
**一度解いた部分問題の答えを再利用**して全体を解く手法です。

メモ化が「再帰＋覚えておく」（トップダウン）なのに対し、
DP では多くの場合 **小さい問題から順にテーブルを埋める**（ボトムアップ）形で書きます。

```
メモ化:  fib(n) を呼ぶ → 必要になったら再帰 → 結果をメモ
DP:      dp[0], dp[1] から始めて → dp[2] → ... → dp[n] を埋める
```

どちらも「同じ部分問題を1回だけ解く」という本質は同じです。

## 例 1: フィボナッチ（ボトムアップ）

AOJ `ALDS1_10_A` の典型です。

```c
#include <stdio.h>

int main(void) {
    int n;
    scanf("%d", &n);

    int dp[50];
    dp[0] = 1;  /* 問題定義に合わせて初期化（AOJ は F0=1, F1=1） */
    dp[1] = 1;
    for (int i = 2; i <= n; i++) {
        dp[i] = dp[i - 1] + dp[i - 2];
    }
    printf("%d\n", dp[n]);
    return 0;
}
```

:::note[AOJ のフィボナッチ定義]
競技プログラミングでは問題ごとに初期値が違います。
ALDS1_10_A は `F(0)=1, F(1)=1` です。数学の教科書の `F(0)=0, F(1)=1` と違うので注意。
:::

### 計算量

| 観点 | 値 |
|:---|:---|
| 時間 | `O(N)` |
| 追加メモリ | `O(N)`（実際は直前2項だけ持てば `O(1)` にもできる） |

## 例 2: 部分和（DP版）

「集合 `A` の部分集合で和 `m` を作れるか」を、ブール値の DP テーブルで解きます。

`dp[j] = true` ⇔ 「これまでに見た要素で和 `j` を作れる」

```c
#include <stdio.h>

int main(void) {
    int n;
    scanf("%d", &n);

    int a[50];
    for (int i = 0; i < n; i++) scanf("%d", &a[i]);

    int q;
    scanf("%d", &q);

    /* 1回のクエリごとにやってもよいが、先に全和の可能性を埋める例 */
    int max_sum = 0;
    for (int i = 0; i < n; i++) max_sum += a[i];

    int dp[2001] = {0};
    dp[0] = 1;  /* 和0は空集合で作れる */

    for (int i = 0; i < n; i++) {
        /* 後ろから更新すると「同じ要素を2回使う」のを防げる */
        for (int j = max_sum; j >= a[i]; j--) {
            if (dp[j - a[i]]) dp[j] = 1;
        }
    }

    for (int i = 0; i < q; i++) {
        int m;
        scanf("%d", &m);
        if (m <= max_sum && dp[m]) printf("yes\n");
        else printf("no\n");
    }
    return 0;
}
```

:::tip[後ろから更新する理由]
`j` を前から更新すると、同じループ内で更新した直後の `dp[j]` を次の `j'` が参照し、
**同じ要素を複数回使った**ことになってしまいます。
0-1 ナップサック／部分和では「後ろから」が定番です。
:::

### 計算量

時間 `O(N × ΣA)`、メモリ `O(ΣA)` です。全探索の `O(2^N)` より大幅に速くなることが多いです。

## 例 3: 最長共通部分列（LCS）

2つの文字列 `X`, `Y` の**最長共通部分列**の長さを求めます（AOJ `ALDS1_10_C`）。

`dp[i][j]` = `X` の先頭 `i` 文字と `Y` の先頭 `j` 文字の LCS 長

```c
#include <stdio.h>
#include <string.h>

int dp[1001][1001];  /* 約4MB。スタック溢れを防ぐためグローバルに置く */

int max2(int a, int b) { return a > b ? a : b; }

int main(void) {
    int q;
    scanf("%d", &q);
    while (q--) {
        char X[1001], Y[1001];
        scanf("%s", X);
        scanf("%s", Y);
        int n = (int)strlen(X);
        int m = (int)strlen(Y);

        for (int i = 0; i <= n; i++) dp[i][0] = 0;
        for (int j = 0; j <= m; j++) dp[0][j] = 0;

        for (int i = 1; i <= n; i++) {
            for (int j = 1; j <= m; j++) {
                if (X[i - 1] == Y[j - 1]) {
                    dp[i][j] = dp[i - 1][j - 1] + 1;
                } else {
                    dp[i][j] = max2(dp[i - 1][j], dp[i][j - 1]);
                }
            }
        }
        printf("%d\n", dp[n][m]);
    }
    return 0;
}
```

### 遷移の意味

| 条件 | 遷移 |
|:---|:---|
| `X[i-1] == Y[j-1]` | 末尾を採用 → `dp[i-1][j-1] + 1` |
| 異なる | どちらか一方を捨てる → `max(dp[i-1][j], dp[i][j-1])` |

計算量は `O(|X| |Y|)` です。

## DP を解く手順（テンプレ）

| ステップ | 質問 |
|:---|:---|
| 1. 状態 | 「何をキーにして答えを覚えるか？」（例: `dp[i]`, `dp[i][j]`） |
| 2. 遷移 | 「その状態は、どの小さい状態から作れるか？」 |
| 3. 初期値 | 「一番小さい問題の答えは何か？」 |
| 4. 答え | 「最終的に欲しいのはどのマスか？」 |
| 5. 計算量 | 「状態数 × 遷移コストは制約に収まるか？」 |

:::important[再帰 → メモ化 → DP]
迷ったら次の順で考えると安定します。

1. まず再帰で正しく動く解を書く
2. 遅いならメモ化を足す
3. 慣れてきたらボトムアップの DP に書き換える
:::

次は、練習問題と AOJ 課題で手を動かしましょう。
